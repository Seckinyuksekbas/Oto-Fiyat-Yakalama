# Uygulama Yol Haritası — Oto Fırsat Platformu

**Spec:** `docs/superpowers/specs/2026-10-10-oto-firsat-platformu-design.md`

Spec'in 9 uygulama dilimi 8 plana bölünmüştür. Her plan kendi başına çalışan, test edilmiş yazılım üretir. **Bir plan, bir önceki plan uygulanıp `main`'e merge edildikten sonra gerçek koda bakılarak yazılır**; böylece sonraki planlar var olmayan arayüzleri tahmin etmez.

| # | Plan | Spec dilimi | Bağımlılık | Teslim |
|---|---|---|---|---|
| 01 | Temel altyapı + kimlik doğrulama | 1, 2 | — | Monorepo, Docker dev ortamı, tam Prisma şeması, CI, NestJS API iskeleti, auth (kayıt/giriş/refresh rotasyonu/şifre sıfırlama/e-posta doğrulama), RBAC, audit, izolasyon matrisi |
| 02 | Toplama hattı | 3 | 01 | `apps/worker` (worker + scheduler rolleri), BullMQ, demo-site, adapter registry, PoliteHttpClient (robots, token-bucket, proxy), normalizer, ingest/dedup, fiyat geçmişi, CollectionJob/ScrapeError, kaynak sağlık durumu, ilan kaybolma tespiti |
| 03 | Analiz motoru | 4 | 02 | `packages/analysis` (rules-v1), `analyze` kuyruğu, gece yeniden analizi, açıklama JSON'u |
| 04 | Arama profilleri + eşleştirme | 5.1–5.3 | 03 | `/me/search-profiles` (+ preview), `confidence_rank` SQL fonksiyonu, eşleştirme sorgusu, ListingMatch, plan limitleri (profil sayısı, günlük bildirim), doğrulanmamış hesap kısıtı |
| 05 | Bildirimler | 5.4–5.7 | 04 | `notify` kuyruğu, IN_APP + SSE, Telegram adapter (polling/webhook, bağlama akışı, inline butonlar), retry, gecikme metriği, `/me/notifications`, `/me/channels` |
| 06 | Web + kullanıcı paneli | 8 (kullanıcı) | 05 | Next.js, "Gece Showroom" tasarım sistemi, auth sayfaları, dashboard, fırsatlar, profiller, ilan detayı (fiyat bandı, emsal grafiği), favoriler, bildirimler, abonelik, ayarlar |
| 07 | Admin paneli | 7 (admin), 8 (admin) | 06 | Admin API'lerinin geri kalanı (ilanlar, analizler, kaynaklar, işler, proxy, kuyruklar, worker'lar, planlar, ayarlar, loglar, SSE) + admin arayüzü + alarmlar |
| 08 | Üretim ve uçtan uca | 9, 11 | 07 | Prod compose (caddy, backup, migrate), Dockerfile'lar, Playwright E2E senaryosu, operasyon dokümanları, restore testi |

## Plan dışı (sonraki spec'ler)
Ödeme entegrasyonu, admin 2FA, OAuth, e-posta/web-push ilan bildirimi, gerçek veri kaynakları (lisans/izin sonrası), ML tabanlı analiz.
