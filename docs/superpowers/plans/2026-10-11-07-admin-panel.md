# Plan 07 — Admin Paneli Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. UI task'larında (10–12) uygulayıcı `frontend-design:frontend-design` skill'ini yükler ve `docs/web.md` kurallarına uyar.

**Goal:** Yöneticilerin sistemi gerçek verilerle yönetip izleyebileceği bir admin paneli: kullanıcılar ve abonelikler, ilanlar/analizler (yeniden analiz), veri kaynakları (dry-run test taraması, etkinleştirme/duraklatma, istatistik), işler, proxy'ler, kuyruklar, worker'lar, bildirimler (yeniden deneme, gecikme p50/p95), paketler, sistem ayarları (analiz katsayıları), denetim ve sistem logları, canlı alarm/KPI akışı; ayrıca Plan 01–06'dan Plan 07'ye taşınan sertleştirmeleri tamamlamak.

**Architecture:** API'de `apps/api/src/modules/admin/*` altında alan başına controller+service; tüm admin mutasyonları kendi transaction'ında `AuditService.recordInTx(tx, …)` ile **atomik** denetim kaydı yazar (`@Audited(action)` yalnızca kapsama meta verisidir). API, kuyruklara `AdminQueues` (BullMQ `Queue` örnekleri) üzerinden erişir; worker'a özgü işler (dry-run tarama, yeniden analiz, bildirim yeniden deneme) kuyruk işi olarak gönderilir. Worker'da `MonitorService` scheduler adımı olarak alarm koşullarını değerlendirir ve `AlertService` (SystemLog + adminlere IN_APP + bağlıysa Telegram + `admin:events` yayını, 30 dk susturma) ile bildirir. Web'de `/admin/*` Plan 06 tasarım sistemiyle; rota koruması middleware + sunucu rol kontrolü.

**Tech Stack:** NestJS 11, Prisma 6, BullMQ 5 (API tarafında Queue + `getJobCounts`/`getJobs`/`retryJobs`/`clean`), ioredis (pub/sub, SCAN), undici (`ProxyAgent` ile proxy kontrolü), Next.js 15 + TanStack Query + Recharts, Vitest + Supertest + Testcontainers + MSW.

**Spec:** `docs/superpowers/specs/2026-10-10-oto-firsat-platformu-design.md` §7 (Admin uç noktaları), §8 (Admin sayfaları), §9 (izleme, alarmlar, metrikler), §6 (Yetkilendirme, Denetim, SSRF/Gizli veriler), §3 (Manuel test taraması), §4.7 (yeniden analiz). Yol haritası: `docs/superpowers/plans/2026-10-10-00-roadmap.md` — tüm "Plan 07" taşınan maddeleri. Web kuralları: `docs/web.md`.

## Global Constraints

- Plan 01–06 Global Constraints maddeleri geçerlidir.
- `/admin/*` → `ADMIN | SUPER_ADMIN`; rol değiştirme, kullanıcı silme, paketler ve sistem ayarları → yalnızca `SUPER_ADMIN`. Rol her istekte DB'den okunur (mevcut `RolesGuard`).
- Her admin mutasyonu atomik denetim kaydı yazar (aktör, aksiyon, hedef, before/after, IP); kapsama testi (`apps/api/test/audit-coverage.e2e.spec.ts`) tüm `/admin` mutasyon route'larında `@Audited` arar.
- Yanıtlar gizli alanları döndürmez: `passwordHash`, kanal `config`, `chatId`, proxy kimlik bilgisi, `urlEncrypted`, bot token; URL sorgu dizileri maskelenir.
- Admin listeleri offset `{ items, total }`, `pageSize ≤ 100`.
- Rate limit: manuel tarama 1/dk/kaynak (spec §6).
- Web: `docs/web.md` kuralları (sorgu anahtarı kökleri, Geist Mono yalnız sayılar, AA kontrast, tek h1, sayfa başlığı metadata ile).
- Kaynak etiği: admin arayüzü yalnızca izinli (`permissionVerifiedAt` dolu) kaynakları etkinleştirebilir; hiçbir ayar/kod scraping kısıtlarını aşma (UA sahteciliği, captcha çözme, proxy rotasyonuyla engel aşma) seçeneği sunmaz.

## Review Focus

1. **ADMIN rolüyle SUPER_ADMIN'e özel işlem (rol, silme, paket, ayar) ya da bir SUPER_ADMIN'i askıya alma:** 403; son süper admin hiçbir yoldan düşürülemez/silinemez/askıya alınamaz (eşzamanlı iki istekte de). → Task 3 testi.
2. **Hatalı ayar kaydı (çapraz alan çelişkisi, bilinmeyen anahtar, yanlış tip):** 400 ve mevcut ayar korunur; geçerli kayıt worker'larda en geç birkaç saniyede etkili olur. → Task 8 testi.
3. **Kaynak `baseUrl` iç ağı gösteriyor (169.254.169.254, 10.x, localhost, DNS ile iç IP'ye çözülen ad) production'da:** reddedilir. → Task 5 testi.
4. **Yinelenen/ısrarlı yeniden deneme tıklamaları (bildirim retry, queue retry-failed, test-scrape):** çift gönderim yok, rate limit/idempotency çalışır, audit tek kayıt. → Task 5, 7 testleri.
5. **USER ve ADMIN ile tüm `/admin` route'ları:** USER her route'ta 403; ADMIN SUPER_ADMIN route'larında 403 (route listesi controller meta verisinden otomatik). → Task 2 testi.
